# Project Steering: mokhaLabSSR

## Overview

This is a fullstack web application built on the [AWS Amplify Next.js App Router starter template](https://github.com/aws-samples/amplify-next-template). It uses **Next.js 14 (App Router)** with **AWS Amplify Gen 2** for backend services. The current app is a real-time Todo list, intended as a foundation for a production application.

> **Note on SSR**: The project is named `mokhaLabSSR` and deployed via Amplify Hosting with Next.js SSR support (`.next` artifacts). However, the current page components use `"use client"` and connect to Amplify directly from the browser. Server Components and Server Actions are available but not yet in use.

## Amplify Backend

### Auth
- Provider: Amazon Cognito
- Login method: email + password
- Defined in: `amplify/auth/resource.ts`

### Data
- API: AWS AppSync (GraphQL)
- Database: DynamoDB
- Current schema: `Todo` model with a `content: string` field
- Authorization: public API key (30-day expiry) — suitable for dev, **update before production**
- Defined in: `amplify/data/resource.ts`
- Client usage: `generateClient<Schema>()` from `aws-amplify/data`

### amplify_outputs.json
Auto-generated by Amplify after each backend deploy. Contains API endpoints, auth config, and API keys. **Never commit secrets here.** This file is already in `.gitignore` for production use; keep it for local dev.

## Development Workflow

### Local development
```bash
npm run dev          # Start Next.js dev server at http://localhost:3000
```

For backend changes, run the cloud sandbox concurrently:
```bash
npx ampx sandbox     # Deploys an isolated backend sandbox (~5 min first run)
```

The sandbox updates `amplify_outputs.json` automatically. It runs alongside `npm run dev`.

### Build
```bash
npm run build        # Production Next.js build → .next/
npm start            # Serve production build locally
npm run lint         # Next.js ESLint
```

### Deploy to AWS
Push to your connected git branch. Amplify Hosting picks it up automatically per `amplify.yml`:
- **Backend phase**: `npx ampx pipeline-deploy` — deploys CDK/Amplify backend
- **Frontend phase**: `npm run build` — builds Next.js, artifacts from `.next/`

Environment variables available in build: `AWS_BRANCH`, `AWS_APP_ID`

## Code Conventions

### TypeScript
- Strict mode is on — no `any`, no implicit returns
- Path alias `@/*` resolves to the project root (e.g. `@/amplify/data/resource`)
- The `amplify/` folder has its own `tsconfig.json` and is excluded from the app tsconfig

### Components
- Client components that use Amplify data/auth must include `"use client"` at the top
- Server Components can be used for non-interactive UI — avoid importing Amplify client libraries in them
- Use `generateClient<Schema>()` to get a typed data client in client components

### Styling
- Global CSS variables are in `globals.css`
- Component styles use CSS Modules (`.module.css`) or scoped CSS files
- Amplify UI styles imported via `@aws-amplify/ui-react/styles.css`

### Amplify Gen 2 patterns
- Backend resources are defined with `defineAuth`, `defineData`, `defineBackend` from `@aws-amplify/backend`
- `Amplify.configure(outputs)` must be called once at the app entry point
- Use `client.models.Todo.observeQuery()` for real-time subscriptions
- Use `client.models.Todo.create/update/delete` for mutations

## Dependency Management

**All dependencies must be installed in the root `package.json` only.**

- `amplify/package.json` exists for documentation purposes — it lists what the backend functions need, but is never used for installation
- Never run `npm install` inside the `amplify/` folder
- Never add packages to `amplify/package.json` as a way to install them
- The Amplify build runs `npm ci` at the root only — anything not in the root lockfile will not be available at build time

When adding a new dependency needed by an Amplify function (e.g. an AWS SDK client), add it to the **root** `package.json` and run `npm install` from the project root.
